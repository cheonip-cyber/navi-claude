01 · PROJECT RULES

가장 먼저, 데이터 사용 규칙을
프로젝트 지침으로 고정합니다.

기능을 먼저 만들기보다 원본 데이터와 계산 규칙을 문서화해야 이후의 화면·추천 기능이 일관되게 동작합니다.

사용자 프롬프트지침파일을 확인해서, 해당 지침을 지속적으로 지킬 수 있도록 세팅해줘.

확인한 핵심 규칙

원본 데이터는 읽기 전용이며, 연결에는 이름이 아니라 ID를 사용합니다. 관계는 employee_id → job_id → level → jqc_id → course_id 순서로 추적합니다.

프로젝트에 남긴 결과

AGENTS.md에 레벨, 이수, JQC, 추천, 일정 규칙을 구조화합니다. 이후 개발 작업은 이 문서를 공통 기준으로 삼습니다.

학습 포인트 · 요구사항을 개발자의 기억에만 의존하지 말고, 프로젝트 안의 지침 파일로 남겨 변경 작업마다 확인합니다.

02 · DATA DISCOVERY

JSON을 먼저 읽고,
실제 필드로 화면을 설계합니다.

사용자 프롬프트json파일을 확인해주고, 직원 교육 네비게이터를 만들고 싶어. 사번을 입력하면 직원의 소속, 직무, 현재 레벨을 보여주고, 다음 단계에 필요한 JQC와 교육을 안내하는 웹앱이야. 한 번에 모든 기능을 만들지 말고, 우선 사번을 입력하고 직원 정보를 확인하는 화면부터 만들어줘.
employees→employee_id→job_id→current_level

확인한 직원 필드

employee_id, department_name, part_name, job_id, job_name, current_level

데이터 규모 파악

직원 15명, JQC 86개, 과정 288개, JQC-과정 매핑 343개를 확인했습니다. 이 수치를 먼저 보면 화면·성능 범위를 판단할 수 있습니다.

03 · FIRST SCREEN

첫 기능은 사번 조회와
직원 정보 표시만 구현합니다.

// 입력값을 대문자 사번으로 정규화 const normalizedId = employeeId.trim().toUpperCase() const employee = employees.find( ({ employee_id }) => employee_id === normalizedId )
  • 빈 값: “사번을 입력해 주세요.”
  • 없는 사번: “직원 정보를 찾을 수 없습니다.”
  • 일치하는 사번: 소속·파트·직무·현재 레벨 표시

왜 한 번에 만들지 않을까요?

조회 기능이 맞는지 먼저 확인해야 다음 단계의 JQC·이수·추천 계산에 잘못된 직원 정보가 전달되는 일을 막을 수 있습니다.

검증 예시: AI00009 입력 시 교육생01, AI 전략기획부, AI 전략기획, LV3가 표시되는지 확인합니다.

04 · NEXT TARGET

현재 레벨은 그대로,
다음 목표만 규칙으로 제안합니다.

사용자 프롬프트현재 레벨 다음에 어떤 레벨을 준비해야 하는지 보여줘. 현재 레벨은 데이터에 있는 값을 그대로 사용해줘. LV1의 다음 목표는 '특급 엔지니어'라고 표시하면 돼. 관련 과정이나 JQC는 없어.
const nextLevelByCurrentLevel = { LV4: 'LV3', LV3: 'LV2', LV2: 'LV1', LV1: '특급 엔지니어', }

반드시 지킬 점

current_level을 재계산하지 않습니다. 교육 이력이나 준비도는 다음 목표를 위한 정보일 뿐 현재 레벨을 바꾸는 근거가 아닙니다.

LV1 예외

특급 엔지니어는 목표 명칭만 표시합니다. JQC·교육·진행률을 임의로 생성하지 않습니다.

05 · TARGET JQC

직무와 목표 레벨이 모두 맞는
JQC만 연결합니다.

사용자 프롬프트다음으로 직원의 직무와 다음 목표에 맞는 JQC를 보여줘. 데이터가 어떻게 연결되는지 먼저 확인하고 구현해줘. 관련 JQC가 없는 경우에는 임의로 만들지 말고 없다는 안내를 보여줘.
employees.job_id→job_jqc_map→jqc_id→jqcs
sourceData.job_jqc_map .filter(mapping => mapping.job_id === result.job_id && mapping.level === targetLevel) .map(mapping => jqcs.find(jqc => jqc.jqc_id === mapping.jqc_id))
빈 데이터 처리 · 연결 결과가 없으면 “현재 직무와 다음 목표 레벨에 연결된 JQC 정보가 없습니다.”를 표시합니다. 데이터에 없는 JQC는 만들지 않습니다.

06 · COMPLETION & READINESS

교육 이력을 필수 과정과 비교해
JQC 준비도를 계산합니다.

사용자 프롬프트이제 직원의 교육 이수내역을 불러와서, 각 JQC를 준비하기 위해 교육을 얼마나 이수했는지 보여줘. 수료와 우수는 이수한 것으로 보고, 재교육은 아직 이수하지 않은 것으로 처리해줘. 진행 정도를 바 형태로 시각화 해줘.
employee_courses→completed course_id→jqc_course_map→준비도

이수 판정

수료·우수 결과의 course_id만 완료 집합에 넣습니다. 재교육은 완료 집합에 넣지 않습니다.

계산식

이수한 연결 교육의 고유 과정 수 ÷ 전체 연결 교육의 고유 과정 수 × 100. 연결 교육이 0건이면 0%가 아니라 교육정보 없음입니다.

상태 문구 · 0% 학습 시작 전 · 1~99% 학습 진행 중 · 100% JQC 평가 준비 완료. 100%는 공식 인증 완료가 아닙니다.

07 · COURSE RECOMMENDATION

준비가 필요한 JQC에서
미이수 필수 과정만 추천합니다.

사용자 프롬프트아직 이수하지 않은 교육을 추천하는 기능을 추가해서 표시해줘. 왜 이 교육이 필요한지 알 수 있도록 관련 JQC도 함께 보여줘. 같은 과정이 여러 번 나오면 한 번만 보여줘.
// course_id를 키로 사용해 중복 통합 const courseMap = new Map() if (!courseMap.has(courseId)) { courseMap.set(courseId, { course, jqcs: [] }) } courseMap.get(courseId).jqcs.push(jqc)

추천 화면에는 과정명, 과정 ID, 목표 레벨, 관련 JQC를 함께 표시합니다. 따라서 학습자는 “무엇을”과 “왜”를 동시에 이해할 수 있습니다.

추천 대상 조건

  • 현재 직원의 목표 JQC에 연결됨
  • REQUIRED 과정임
  • 현재 이수 상태에 없음
  • 과정 ID가 중복되면 한 카드로 통합

08 · QUALITY CHECK

화면을 만든 뒤에는
데이터와 빌드를 같이 점검합니다.

사용자 프롬프트지금까지 개발한 코드 점검해 봐.

자동 확인

npm run lint npm run build

문법·정적 오류를 확인하고, 실제 배포용 번들이 생성되는지 검증합니다.

데이터 무결성 확인

job_jqc_map.jqc_id가 실제 JQC에 존재하는지, jqc_course_map.course_id가 실제 과정에 존재하는지 확인합니다.

코드 점검 결과 · 린트와 프로덕션 빌드 통과, JQC·과정 참조 누락 0건을 확인했습니다. 이후 데이터가 커질 때는 ID별 인덱스를 만들어 반복 순회를 줄이는 개선을 권장합니다.

09 · VERSION CONTROL

작동하는 시점마다 커밋하고,
저장소에는 필요한 파일만 올립니다.

사용자 프롬프트'navi-2'라는 이름으로 깃허브에 업로드해줘.
1
저장소 범위 결정

웹앱 소스, JSON 실습 데이터, 지침 파일을 포함하고 불필요한 엑셀 원본·빌드 산출물은 제외합니다.

2
비공개 저장소 생성

저장소 공개 범위를 확인한 뒤 GitHub에 navi-2를 비공개로 만듭니다.

3
의미 있는 단위로 커밋

초기 화면과 JQC 기능을 별도 커밋으로 남겨 변경 이력을 이해하기 쉽게 만듭니다.

주의 · 코드가 수정된 뒤에는 git status로 미커밋 변경을 반드시 확인합니다. 로컬에서 정상이어도 푸시하지 않으면 GitHub 버전에는 반영되지 않습니다.

10 · REPRODUCTION CHECKLIST

학습자가 따라 할
권장 개발 순서

  1. 지침 파일을 읽고 프로젝트 규칙으로 정리한다.
  2. JSON 구조·ID 관계·예시 직원 데이터를 확인한다.
  3. 사번 조회와 직원 정보 표시부터 구현·검증한다.
  4. 다음 목표 레벨, 목표 JQC를 순차적으로 추가한다.
  5. 교육 이력·준비도·미이수 추천을 구현한다.
  6. 빈 결과와 LV1 예외를 화면으로 명확히 처리한다.
  7. 린트·빌드·데이터 참조를 검증하고 커밋한다.
